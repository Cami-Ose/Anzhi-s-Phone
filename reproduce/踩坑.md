# 踩坑

只收编 ROM、刷 ROM、首次开机这条线上真会撞到的。开发期的坑（IPC 死锁、VirtualDisplay、SQLite、CDP 那一批）不在这里。

## SELinux 放到最后做 = 死路

priv-app 里的系统服务要同时干跨域的事：网络、文件 IO、注入事件、截屏。全写完再补 `.te`，结果是 `avc: denied` 海啸，系统卡在开机动画，连日志都难读。

**做法**：地基一开始就做。开发期设 Permissive，`adb logcat | grep avc` 收集拒绝日志，每上一个功能同步补规则，最后一版编 Enforcing。

```bash
adb shell setenforce 0        # 临时切 Permissive，不刷机
./scripts/collect_avc.sh -p   # 生成 .te 建议
```

## Deep Doze 会掐掉网络和闹钟

手机拔充电线、熄屏静置半小时以上，内核进 Deep Doze：网络 IO 被断（WebSocket 掉线），普通 `AlarmManager` 的闹钟被无限期挂起。醒来那一刻积压的闹钟一起炸出来。

**做法**：

- 唤醒闹钟用 `setExactAndAllowWhileIdle()`，不用普通 `set()`
- 进程加进 Doze 白名单（见[首次开机.md](首次开机.md)）
- Data Saver 是另一套封杀策略，Doze 白名单管不了它，户外省电模式开着照样断网，要单独加 `netpolicy` 白名单

## system_server 崩一次就无限重启

安知服务跑在系统特权空间。磁盘写满、或者 WebSocket 报文 JSON 解析异常没被 catch，都会把 `system_server` 带崩 → 内核杀 Zygote → 整机软重启。如果崩在开机初期读会话库那一步，每次启动都崩，只能线刷。

**做法**：

- `onCreate()` 里的初始化全部包 try-catch，异常时把 crash 日志写到 `/data/local/tmp/`，不写 SQLite
- 开机 5 分钟内崩够 3 次，第 4 次启动跳过所有初始化，只显示错误界面等 adb 介入。计数器用纯文本文件，不依赖数据库
- 所有 SQLite 写操作前查剩余空间，低于 50MB 就拒绝写并清旧数据
- WebSocket 的 JSON 解析包 try-catch，解析失败记原始报文后丢弃，不抛

## WebSocket 固定间隔重连

断线后每 3 秒重连一次。碰上服务器挂了或者被墙，一晚上就 3→3→3 无限重连，烧电池刷日志。

**做法**：指数退避 3→6→12→24→60 秒封顶；连着重连 10 次后改成 5 分钟一次；连上就重置计数器。半夜（0:00–6:00）间隔再乘 2。

## XML 注释里不能出现 `--`

`m vendorimage` 跑到第四分钟，aapt2 报 `xml parser error: not well-formed (invalid token)`，指向的那行是一句普通中文注释。XML 1.0 规定注释内部不许有 `--`，在注释里写命令行（`settings get secure --user 0 …`）就踩雷，而且只报列号不报原因。

**做法**：编译前先严格解析一遍，几秒定性，别拿四分钟去撞。

```bash
python3 - "$OV" <<'PY' || { echo "### PREFLIGHT FAIL xml"; exit 1; }
import sys, xml.etree.ElementTree as ET
try: ET.parse(sys.argv[1])
except Exception as e: print("PREFLIGHT XML ERROR:", e); sys.exit(1)
PY
```

同一条规矩对 `AndroidManifest.xml` 的 xmlns 也适用。

## vendor RRO 压不过 product RRO

改 framework 资源（overlay 里那份 `config.xml`）不一定生效，而编译产物里的值也不代表设备上的值。

真机上同一个资源 id 出现两个覆盖者时，按 `mPriority` 高者赢。实测 Lineage 的 `auto_generated_rro_product__` priority 是 19，我们 `DEVICE_PACKAGE_OVERLAYS` 落到 vendor 的那份是 2 —— **vendor 侧写的永远压不过 Lineage 在 product 侧写的那份**。分区顺序决定的，不是笔误。

**判据**（凡是靠 framework 资源生效的行为都这么查）：

```bash
# ① 这个资源 id 有几个覆盖者、各在哪个分区、priority 多少
adb shell cmd overlay dump > /tmp/ov.txt      # 别 head，几千行
grep -n "0x<资源id>" /tmp/ov.txt              # 用 id 找，别用资源名找

# ② 读消费者自己打的运行时 dump
adb shell dumpsys window | grep -i "long.*press.*power"
```

只有一个覆盖者时 priority 无意义，有多个才比高低。

**出路按代价排**：① 走 AOSP 留的 Settings 覆盖口（很多 `config_*` 配了对应的 Global/Secure 键，注释里写着 `Overrides internal R.integer.xxx`），播种一次就行，不用重编；② 真要改资源，得放进 product 侧且 priority 高过 19，顺序由构建决定，不可靠；③ 改 `vendor/lineage/overlay/common/…` 那份上游公共文件，要 `m productimage`，最贵。

## 树里有仓库不存在的手工改动

AOSP 树和仓库是两个现场。有人在树里直接改过文件，仓库没有对应改动，`--deploy` 永远盖不掉它，改动会一直活着而且没人知道。

开工前先看：

```bash
repo forall -c 'git status -uno --porcelain' | grep -v '^$'
```
