# 源码

## 1. 拉 LineageOS

```bash
mkdir -p ~/lineageos && cd ~/lineageos
repo init -u https://mirrors.tuna.tsinghua.edu.cn/git/LineageOS/android.git -b lineage-23.2
```

分支是 `lineage-23.2`（Android 16 / SDK 36）。仓库里 `local_manifests/anzhi.xml` 的头注释写的是 Android 15 / LineageOS 22.1，那是 7 月那版配方留下的，别照着走。

init 完检查 `.repo/manifests/default.xml`，把 github 和 aosp 两个 remote 指到清华源，不然 sync 会被墙：

```xml
<remote name="github" fetch=".." />   →  fetch="https://mirrors.tuna.tsinghua.edu.cn/git/"
<remote name="aosp" fetch=".." />     →  fetch="https://mirrors.tuna.tsinghua.edu.cn/git/AOSP/"
```

## 2. 两份 local manifest

都放 `.repo/local_manifests/`。

**anzhi.xml**：把仓库里的 `local_manifests/anzhi.xml` 拷过去。里面绝大多数 project 是注释掉的，它实际是份配方说明 —— 真正把文件放进树里的是 `build_rom.sh --deploy`，不是 repo。

**bluejay.xml**：仓库里没有这份，内容在下面，自己存成 `.repo/local_manifests/bluejay.xml`。前四条是 Pixel 6a 的设备仓，最后一条是 TheMuppets 提取的闭源固件和驱动。少了最后一条，sync 完的树里没有 HAL，编不到底。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<manifest>
  <project name="LineageOS/android_device_google_bluejay" path="device/google/bluejay" remote="github" revision="lineage-23.2" />
  <project name="LineageOS/android_device_google_gs101" path="device/google/gs101" remote="github" revision="lineage-23.2" />
  <project name="LineageOS/android_device_google_gs-common" path="device/google/gs-common" remote="github" revision="lineage-23.2" />
  <project name="LineageOS/android_device_google_bluejay-kernels" path="device/google/bluejay-kernels" remote="github" revision="lineage-23.2" />

  <!-- 闭源固件、驱动、HAL -->
  <project name="TheMuppets/proprietary_vendor_google_bluejay" path="vendor/google/bluejay" remote="github" revision="lineage-23.2" />
</manifest>
```

本地树里还有一份 `aosp_overrides.xml`，把 5 个模块换成 AOSP 上游。那是更早留下的，这份指引没有验证它是否必需。

## 3. sync

```bash
repo sync -j4
```

170GB 左右，挂一晚上。

## 4. 上游补丁

有几处改动落在 LineageOS 和 Google 自己的文件里，仓库没有对应位置可以放，记在 `patches/`。`build_rom.sh` 部署时会自动套（`apply_upstream_patches`），套不上直接停，不静默继续编。

手工套法和每份补丁改了什么，见 [patches/README.md](../patches/README.md)。前提是 `lineage-23.2`；行号会随上游漂移，打不上就按资源名手改，别硬 fuzz。

## 5. 一个不在仓库里的构建输入

`app/libs/okhttp-4.12.0.jar` 没有进 git，要自己放。它是 `app/libs/Android.bp` 里 `java_import "anzhi-okhttp"` 的唯一输入，缺了必编不过。

从 Maven Central 取 `com.squareup.okhttp3:okhttp:4.12.0`，放进 `app/libs/`。789531 字节，md5 `6acba053af88fed87e710c6c29911d7c`。
