# 构建

入口是仓库根目录的 `scripts/build_rom.sh`。

## 先告诉它源码在哪

脚本会自己猜源码目录（在 WSL 的 `/mnt/` 下按 `Anzhi*Phone` 这个名字找）。猜不中或者你的路径不同，显式给：

```bash
export ANZHI_SRC=/path/to/Anzhi-s-Phone
```

## 六个参数

| 参数 | 干什么 |
|---|---|
| `--verify` | 只检查环境（内存、磁盘、工具链），不编译，最后打印刷机和验证清单 |
| `--deploy` | 只把源码放到树里的生效路径，不编译 |
| `--anzhi-only` | 部署 + 编 AnzhiOS / AnzhiCore，验证 Kotlin 编得过 |
| `--full` | 部署 + Enforcing + `mka bacon` 全量编（默认） |
| `--dev` | 部署 + Permissive + 只编安知部分 |
| `--clean` | 先 installclean 再全量编 |

第一次走 `--verify` → `--deploy` → `--anzhi-only`，都过了再 `--full`。能省掉好几次一小时的空跑。

## --deploy 把文件放哪

这一步别手工 `cp`，路径放错就是白编一轮。

| 仓库里的 | 树里的 | 谁让它生效 |
|---|---|---|
| `app/` | `packages/apps/AnzhiOS/` | `Android.bp` 的 `privileged: true` + `system_ext_specific: true` |
| `sepolicy/` | `vendor/anzhi/sepolicy/` | `BOARD_SEPOLICY_DIRS` |
| `vendor/anzhi/anzhicore/` | 同名 | 编成 AnzhiCore |
| `vendor/anzhi/privapp-permissions/` | 同名 | `PRODUCT_COPY_FILES`，打进 `system_ext/etc/permissions` |
| `vendor/Android.mk` | `vendor/anzhi/Android.mk` | 两边名字不一样，别留第二份 |
| `device/bluejay/device.mk` | `device/anzhi/bluejay/device.mk` | `lineage_bluejay.mk` 末尾的 `inherit-product` |
| `device/bluejay/BoardConfig.mk` | `device/google/bluejay/BoardConfig_anzhi.mk` | `bluejay/BoardConfig.mk` 末尾的 `include` |
| `device/bluejay/overlay/…` | `device/anzhi/bluejay/overlay/…` | `DEVICE_PACKAGE_OVERLAYS`，编成 `/vendor/overlay` 里的静态 RRO |
| `local_manifests/anzhi.xml` | `.repo/local_manifests/anzhi.xml` | repo |

`app/` 用 `rsync --delete` 同步，仓库侧删掉的文件树里也跟着删。`include` 和 `inherit-product` 两行是幂等注册，写过就跳过。另外脚本会把 `device/google/bluejay/` 下几个孤儿文件（`device.mk`、`device_anzhi.mk`、`BoardConfig.mk` 等）移进 `.anzhi-stale/<时间戳>/`，是移走不是删。

`device/google/bluejay/` 下**没有**上游 `device.mk`，产品入口是 `lineage_bluejay.mk`。把配置写进 `device/google/bluejay/device.mk` 永远不会被读到 —— 7 月那版就是这么丢的。

## 产物

在 `out/target/product/bluejay/`：

- OTA zip（`mka bacon` 出）
- `boot.img` / `dtbo.img` / `vendor_boot.img` / `vbmeta.img` / `vbmeta_system.img` / `vbmeta_vendor.img`
- `system.img` / `system_ext.img` / `vendor.img` / `product.img`

安知 APK 装在 `system_ext/priv-app/AnzhiOS/`，不是 `system/priv-app/`。

SELinux 模式：`--full` 收 Enforcing，`--dev` 留 Permissive（脚本会改 `bluejay/BoardConfig.mk` 的 kernel cmdline）。

编完脚本会核一遍产物是不是本轮新出的，源码比产物还新就报错退出，别忽略那句。

## 树里的手工改动

AOSP 树和这个仓库是两个现场。有人直接在树里改过文件，而仓库里没有对应改动，`--deploy` 就永远盖不掉它。

开工前先看一遍：

```bash
repo forall -c 'git status -uno --porcelain' | grep -v '^$'
```

有 diff 就对着仓库核一下，是不是该搬回仓库。
